# Durable run persistence

`RunDatabase` owns one private `run.sqlite` and its short synchronous transactions. It uses WAL, FULL synchronization, foreign keys and a five-second busy timeout. POSIX directories/files are 0700/0600. Windows storage has explicit current-user ownership and protected ACLs granting only that user and SYSTEM. Provider work, serializer callbacks and observer delivery never execute inside a database transaction.

`RunLedger.initialize(database, frozenInput)` records the frozen request, definition, identity and budget. `RunLease.acquire(owner)` returns an owner/epoch fencing token. Every execution mutation checks that token in its business transaction; a replacement owner invalidates late results. Heartbeats are fifteen seconds and leases expire after sixty seconds. Active duration excludes released leases and human pauses, and stops accruing when an owner lease expires.

Construct `RunLedger(database, token, { maxTransitions })` and `SqliteRunSaver(database, ledger, { onEvents })`. The execution adapter calls `enter(NodeAdmission)`, checks `resultFor(frame)` before effects and returns `terminal(frame, result)` in the engine-owned `$commit` channel. `putWrites` atomically saves LangGraph pending writes, the attempt result, candidate/receipt proposals and sequenced events. The aggregate checkpoint follows in `put`; it is not part of a fabricated wrapper transaction. Observer failures cannot roll back completion.

The public node namespace in `ExecutionInfo` differs from the parent namespace passed to the saver. Visits retain the public task identity. The saver binds its namespace separately using a unique thread/checkpoint/task match, without parsing opaque namespace strings. Retries keep the same visit and allocate physical attempts durably. Interrupted human nodes retain their attempt; uncertain writes use staged `prepareInterruption` evidence plus the actual `__error__` pending write and require `authorizeRecovery`. Completed failed/blocked outcomes are also reusable results.

`startInvocation` reserves shared budget and returns a durable per-attempt ordinal. `settleInvocation` records null-safe provider usage once; an optional `{ key, value }` memo commits in the same transaction. `readPieceState`/`writePieceState` isolate data by run/scope/node. `session:` keys may evolve; `memo:` keys are immutable and bounded to 2 MiB. `readScopedPieceState`/`writeScopedPieceState` share only `session:` data with a validated ancestor node inside the same scope, preserving developer/fixer continuation without sharing branch sessions. `scopeSnapshot("*")` projects every scope; `interrupts`/`answerInterrupts` retain idempotent answers across a crash before `Command.resume`. `scopeSnapshot` and `events(afterSequence)` expose committed projections without exposing a database to domain pieces.

A started invocation with no settlement makes aggregate usage unknown while retaining reported lower bounds. Its reservation survives owner death, recovery and forks. Settlement releases only dimensions reported by the provider: missing cost retains its cost bound, and missing input/output tokens retain the original token bound minus known tokens. These residual bounds consume future headroom but are never reported as billed usage. `reservationStatus()` separates running invocation count, reserved bounds and unknown bounds. The owner calls `settlePause()` after the graph becomes idle so completed siblings cannot leave a human-interrupted run marked running.

`database.forkAt(stagedDestination, { revision, runId, omitPieceStatePrefixes? })` copies a complete historical database cut while holding an inactive-source writer reservation. Append-only row revisions preserve overwritten special writes, all child namespaces and original serialized blobs. It retains opaque checkpoint thread IDs inside the new database, preserves prior budget consumption, drops control messages/provider sessions and suppresses inherited accounting events. The default omitted piece-state prefix is `session:`. The run adapter owns validated state patches, repository/artifact checks and atomic publication of the staged directory.

`forkRun(directory, { fromNodePath, runId, scopeId?, visit?, state?, registry? })` publishes that cut. Only `$vars` and `$outputs` accept bounded JSON patches; patches invalidate inherited verification because they can change verification inputs. Completed implementations retain their original receipt and logical candidate-scope snapshot without rebinding or executing providers again. Actual workspace edits still invalidate those receipts. Incomplete implementations restore immutable journal objects from the selected cut and revalidate verification/review on their existing public child checkpoint. Source SQLite rows, journal bytes and receipts remain unchanged.

Build before running `vitest run src/agent-runtime/engine/checkpoint`, because the killed-child fixtures exercise the compiled production adapters. Tests cover five real process-death boundaries, rollback and conflicting replay, epoch fencing, shared reservations/unknown usage, typed checkpoint history, interrupted writes, immutable root/nested forks, completed siblings and historical accounting. The compiler's separate SQLite integration tests cover production node admission and graph coordination together.

Only an explicit `result.verified` from an admitted `verify` or `implementation` piece can install certification, matching the current candidate and a valid full receipt with actual commands and no unverified repositories. Invalid/scoped receipts remain evidence; `verified: null` explicitly invalidates certification.
