## Why

The programmatic workflow currently recreates OpenSpec documents and archive behavior instead of letting its agents execute the official workflows. Provider-specific skill activation and restricted role tools prevent authentic OpenSpec usage.

## What Changes

- Execute the pinned external OpenSpec framework and load its generated official workflow skills for architect, developer and reviewer.
- Add provider-aware skill activation and scoped OpenSpec tools, retaining LangGraph orchestration and host-owned delivery.
- Replace architect document JSON and manual spec replacement with real change artifacts, validation and archive.
- Bind recovery to the OpenSpec version, skill identities and change scope; retain independent acceptance and verification receipts.
- Fail before paid work when required capabilities are unavailable.

## Capabilities

### New Capabilities
- `openspec-role-workflows`: Authentic, scoped OpenSpec execution by programmatic roles across CLI providers.

### Modified Capabilities

None.

## Impact

Core runtime role protocol, CLI adapters, artifact gates, external dependencies and recovery; Desktop runtime environment and packaged OpenSpec resolution. Existing runs must retain their original protocol or be explicitly identified as incompatible, never silently reinterpreted as delta changes.
